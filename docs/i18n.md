# 화면 언어 (i18n)

화면은 한국어(`ko`, 기본)와 영어(`en`)로 보인다. 사용자는 상단 바의 사용자 메뉴(작업 화면·공유 페이지) 또는 화면 설정(피드·도움말) 팝오버에서 언어를 고른다.

## 구조

| 위치 | 하는 일 |
|---|---|
| `src/shared/config/locale.ts` | 언어 목록, 기본 언어, 저장 키, 첫 페인트 전에 `<html lang>`을 적는 스크립트 |
| `src/shared/lib/i18n.ts` | 고른 언어(localStorage), `defineMessages`, `useT`, `t`, `useLocale`, Intl 헬퍼 |
| `src/features/switch-locale` | 언어 선택 |

정적 export라 서버가 언어를 알 수 없다. 고른 언어는 localStorage에 두고 테마와 같은 방식으로 읽는다. 정적 HTML(SSR)과 테스트는 기본 언어(`ko`)로 그린다.

## 문구 쓰는 법

문구는 쓰는 slice 안에 언어별 표로 둔다. 한곳에 모은 사전 파일은 두지 않는다.

```tsx
const messages = defineMessages({
  ko: { title: "필터", rows: (n: number) => `${n.toLocaleString("ko-KR")}행` },
  en: { title: "Filter", rows: (n: number) => `${n.toLocaleString("en-US")} rows` },
});

function Panel() {
  const text = useT(messages); // 언어가 바뀌면 다시 렌더한다
  return <h2>{text.title}</h2>;
}
```

- `en`은 `ko`와 같은 키·같은 함수 모양이어야 한다 (타입이 검사한다).
- 컴포넌트 밖의 함수(라벨 표, 오류 문구, 차트 툴팁)는 `t(messages)`로 지금 언어의 표를 읽는다. 모듈 위의 상수(`const LABEL = {...}`)는 처음 언어에 묶이므로 함수나 표 + `t`로 바꾼다.
- `t`는 구독하지 않는다. `t`로 만든 문구를 그리는 컴포넌트는 `useLocale()`(또는 `useT`)를 불러 언어가 바뀌면 다시 그린다. `useMemo`로 문구를 만들면 `locale`을 의존성에 넣는다.
- 날짜·숫자 포매터는 `localeCached`로 언어마다 하나씩 만든다 (`dateTime().format(at)`). `toLocaleString()`에는 `intlLocale()`을 넘긴다.

## 번역하지 않는 것

- 제품 이름 `vis-a-lot`, 그리고 사용자·서버가 정한 데이터(데이터셋·컬럼 이름, 게시물 제목, 사용자 이름, 그룹 이름 등).
- 이미 영어로 적은 화면 이름(upload, datastore, gallery, history, shares, feed, help, draw 등)은 두 언어에서 같다.
- 코드 주석과 테스트 이름.

## 레이아웃

언어를 바꿔도 상단 바·도구 줄·버튼의 높이와 자리가 바뀌지 않아야 한다.

- 영어 문구는 한국어와 비슷한 길이로 짧게 쓴다. 상단 바·도구 줄·탭·버튼의 문구는 한 줄로 두고(`whitespace-nowrap`, 필요하면 `truncate`), 높이는 정해진 크기(`h-7.5` 등)를 그대로 쓴다.
- 상단 바·탭·배지처럼 옆에 다른 요소가 붙은 짧은 글자는 `StableText`(`src/shared/ui/StableText.tsx`)로 그린다. 두 언어를 한 칸에 겹쳐 긴 쪽 폭을 잡아 두므로 언어를 바꿔도 옆 요소가 움직이지 않는다.
- 서버 컴포넌트(도움말)는 훅을 쓸 수 없으니 `Localized`(긴 글, 본문)나 `StableText`(짧은 글자)로 두 언어를 함께 그리고 `<html lang>`에 맞는 쪽만 보인다 (`lang-en:` 변형).
- 언어 선택·테마 선택처럼 고르는 값에 따라 글자가 바뀌는 곳은 폭을 고정하거나 같은 비율(`flex-1 basis-0`)로 나눈다.
- 사용자 메뉴의 트리거에는 사용자 이름만 둔다 (화면 언어와 상관없는 글자).

## Lingui (실험: refactor/i18n-lingui)

일부 slice(언어·테마 선택, 사용자 메뉴, 화면 설정, 도움말 셸·문서, 홈 피드, `entities/post`의 라벨·활동 문장, `shared/lib/time`)는 Lingui 매크로로 옮겼다. 나머지는 위의 `defineMessages`를 그대로 쓰고, 고른 언어(`setLocale`)가 두 쪽을 함께 바꾼다.

- 원문은 한국어다. 컴포넌트는 `<Trans>로그아웃</Trans>`, 속성은 `const { t } = useLingui(); t\`사용자 메뉴\``, 모듈 위 표는 `msg\`미해결\``, 컴포넌트 밖 함수는 `@lingui/core/macro`의 `t`·`plural`·`select`를 쓴다. 서버 컴포넌트는 `t(linguiFor(lang))\`위치\``(`shared/lib/lingui.ts`).
- 카탈로그는 slice의 `config/locales/{ko,en}.po`(application은 `messages.{ko,en}.po`)에 있고, slice의 `config/messages.ts`가 컴파일한 카탈로그를 `registerCatalog`로 등록한다. 그 slice의 파일은 `import "../config/messages"`로 이 파일을 불러온다. `config/messages.ts`가 있는 slice만 `lingui.config.ts`가 카탈로그로 잡는다.
- 문구를 바꾸면 `pnpm lingui:extract`로 `.po`를 고치고 `en.po`의 `msgstr`을 채운다. `pnpm build`는 `lingui check sync`(추출 누락)와 `lingui compile --strict`(영어 누락)에서 멈춘다. 컴파일한 `*.ts` 카탈로그는 커밋하지 않는다 (`dev`·`build`·`test`가 만든다).
- 조사는 `josa()`로 붙이지 않고 받침을 `select` 인자로 넘긴다: `` t`상태를 ${from} → ${to}${select(toB, { none: "로", rieul: "로", other: "으로" })} 바꿨습니다` ``. 영어 번역은 그 인자를 쓰지 않는다.
- ICU에서 `'`는 이스케이프 문자다. 문구에 작은따옴표를 쓰려면 `''`로 적는다 (`'{item}'`은 자리표시자가 아니라 글자 `{item}`이 된다).
- id는 원문(+context)으로 만든다. 다른 slice에서 같은 한국어를 다른 뜻으로 쓰면(상태 "취소" ↔ 버튼 "취소") `msg({ message, context })`로 나눈다. 카탈로그를 slice마다 나눠도 실행 중에는 한 표로 합쳐진다.

# 피드 1차 프로토타입

사내 데이터 공유 피드(차트·이미지·동영상·코드를 게시물로 올리고, 게시물에 요청자·담당자·이해관계자·기한·진행률을 붙여 이슈로 다루는 서비스)의 1차 프로토타입이다. vis-a-lot 안의 `/feed` 아래 화면으로 만들고, 같은 출처라 vis-a-lot의 차트 공유를 차트 게시물로 바로 받는다.

1차의 목표는 **"업무 기록 → 내 작업 → 주간 보고"** 흐름이 프로토타입 안에서 끝까지 돌아가는 것이다. 차트·데이터 연결은 게시물 형식(format)과 썸네일, vis-a-lot 차트 공유 가져오기만 넣는다.

## 용어

| 용어 | 뜻 |
|---|---|
| 게시물(post) | 피드에 올리는 단위이자 이슈. 형식(format)은 차트·이미지·동영상·코드 |
| 게시물 유형(post type) | 그룹 관리자가 정하는 단일 선택 라벨(색). 버그·기능·질문·데이터 요청·업무 기록 |
| 그룹 | 프로젝트. 보드 하나, 이슈 키 접두사 하나. 팀은 그룹 안의 스윔레인·필터 |
| 이슈 키 | 그룹 접두사 + 번호 (예: `FD-123`) |

## 범위

| 들어가는 것 | 빠지는 것(2차 이후) |
|---|---|
| 상태 6개 + 카테고리, 우선순위 5단계, 이슈 키, 변경 이력 | 캘린더·타임라인 뷰 |
| 상위/하위·차단·중복·관련 관계, 체크리스트 | 지표 대시보드, CSV·PDF 내보내기, 예약 발송 |
| 홈 피드, 내 작업, 리스트, 보드, 저장된 뷰, 옆 패널 | 차트·이미지 주석, 설명 수정 이력, 동시 편집 |
| 빠른 생성 + 전체 폼, 일괄 작업 | 규칙 자동화 UI, 웹훅, GitLab, MCP |
| 댓글(대댓글·반응·투표·첨부), 멘션, 스레드 해결, 활동 로그 | 텍스트 → SQL → 차트, 차트 해석 |
| 이벤트별 알림, 기한 알림, 구독, 알림함, 알림 설정 | 슬랙·이메일 실제 발송(발송 로그로 흉내) |
| 활동 보고, 현황 보고, 발표 모드, 보고 템플릿 | PWA·푸시, 다국어 |
| 보고 초안 AI(Chrome 내장 또는 흉내), 유형·우선순위·담당자 추천 | 중복 감지, 자연어 검색 |
| 역할 3단계, 그룹 설정(게시물 유형·멤버), 최소 관리 콘솔 | 감사 로그 화면, 휴지통 UI(소프트 삭제 자체는 1차) |
| 커맨드 팔레트, 전역 다크 모드, 반응형 | 단축키 전체, 온보딩 |
| vis-a-lot 차트 공유 → 차트 게시물 | |

## 이 저장소에 맞춘 결정

원래 범위는 독립 앱(Vite + TanStack Router)을 전제로 했다. vis-a-lot 안에 두면서 아래를 바꿨다.

| 원래 | 여기서 | 이유 |
|---|---|---|
| Vite + TanStack Router | Next 라우트(`app/feed/**`) | vis-a-lot과 같은 출처·같은 셸. 정적 export라 동적 경로 대신 query를 쓴다 |
| 모의 API = PGlite SQL을 바로 부르는 TS 모듈 | 피드 REST 서비스 `/api/feed`(Hono + zod, OAS → 생성 타입) + DB Worker 안의 op | vis-a-lot의 다른 서비스와 같은 구조. 실서버로 옮길 때 화면은 그대로다 |
| PGlite 단독 DB | vis-a-lot PGlite의 `feed` 스키마 | DB Worker 하나를 같이 쓰고 테이블 이름이 겹치지 않는다 |
| shadcn/ui | 저장소의 Tailwind 토큰·`tv()` recipe·base-ui (`docs/styling.md`) | 한 저장소에 두 디자인 시스템을 두지 않는다 |
| TanStack Router·Query·Table, dnd-kit, Tiptap | TanStack Query·Table, dnd-kit, Tiptap | 라우터만 Next로 바뀐다 |
| `posts`에 키 컬럼 없음 | `posts.key` 저장 | key_prefix를 바꿔도 기존 키를 유지한다 |
| 상태 이름 저장 위치 없음 | `groups.status_names` | 그룹 설정에서 상태 이름만 바꾼다(카테고리는 고정) |

로그인은 없다. 상단의 사용자 전환으로 고른 사용자 id를 `x-feed-user` 헤더로 보내고(`src/feed/model/current-user.ts`), 서비스가 그 사용자로 권한을 확인한다.

## 구조

```
[화면 src/feed/**, app/feed/**] ──fetch──▶ [MSW gateway] ──▶ [feed 서비스 server/services/feed]
                                                              │ modules/<모듈>/{schemas,routes,handlers}.ts
                                                              │ feedCall(c, 'posts.create', args)
                                                              ▼
                                              [DB Worker] runFeedOp → server/feed/<모듈>.ts op
                                                              │ 트랜잭션 하나: 바꾸기 → recordEvent → dispatch
                                                              ▼
                                                    PGlite `feed` 스키마 (server/feed/ddl.ts)
```

- op는 `defineOps({ '모듈.함수': async (ctx, args) => … })`로 정의하고 `server/feed/ops.ts`가 모은다. `ctx = { db(트랜잭션), actor, now }`.
- "지금"은 항상 `ctx.now`다(`/feed/dev/clock`의 오프셋이 반영된다). DB 기본값 `now()`에 기대지 않는다.
- 도메인 오류는 `throw new FeedError(상태, 메시지)`. 서비스가 같은 HTTP 상태로 돌려준다.
- 쓰기 op는 바뀐 필드마다 `recordEvent`를 부른다. 알림은 `recordEvent` → `dispatchEvent`가 만든다.
- API 타입은 서비스의 zod 스키마가 정하고, 화면은 `src/shared/api/generated/feed.ts`(생성물)만 쓴다.

## 화면과 경로

정적 export라 동적 부분은 query로 받는다. 게시물 상세는 어느 목록에서든 `&peek=<키>`로 옆 패널에 열고, 전체 페이지 경로도 따로 둔다.

| 화면 | 경로 | 핵심 기능 |
|---|---|---|
| 홈 피드 | `/feed` | 그룹 탭별 카드 피드(썸네일·제목·상태·담당자·기한), 상단 내 작업 요약 띠(담당 n, 승인 대기 n, 기한 임박 n), 끌어올리기(pin) |
| 내 작업 | `/feed/my` | 담당 / 내가 요청 / 승인 대기 / 이해관계자 탭, 기한순, 옆 패널 |
| 리스트 | `/feed/list?g=FD` | 열 선택·정렬·그룹핑(상태·담당자·우선순위), 다중 선택 일괄 변경, 옆 패널 |
| 보드 | `/feed/board?g=FD` | 상태 열 칸반, 드래그로 상태 변경(검토 중 열로 옮기면 완료 요청), 팀 스윔레인 |
| 저장된 뷰 | `/feed/view?id=…` | 필터 + 표시 방식(피드·리스트·보드) + 정렬·그룹핑. 개인/그룹 공유, 사이드바 고정. 탐색·관심은 기본 제공 뷰 |
| 게시물 상세 | `/feed/post?key=FD-12` (옆 패널 겸용) | 본문(Tiptap), 필드 패널(상태·우선순위·담당자·요청자·이해관계자·기한·진행률), 체크리스트, 관계, 댓글·활동 로그 타임라인, 완료 요청·승인·반려·보류·취소, 구독 켜기/끄기 |
| 빠른 생성 | 모달(C 키, 팔레트) | 제목 + 그룹, 나머지 기본값. 만든 뒤 옆 패널로 열림 |
| 전체 폼 | `/feed/new` (`?share=<공유 id>`) | 형식(차트·이미지·동영상·코드), 게시물 유형, 우선순위, 그룹·팀, 제목·설명, 요청자·담당자·이해관계자, 기한, 체크리스트, 파일·링크·태그, AI 추천. `share`가 있으면 vis-a-lot 차트 공유로 차트 게시물을 채운다 |
| 활동 보고 | `/feed/report/activity?g=FD` | 기간·팀·담당자 → 날짜순·담당자별 활동 로그. "초안 만들기"(AI). 템플릿 저장 |
| 현황 보고 | `/feed/report/status?g=FD` | 상단 숫자(상태별·기한 초과·담당자별 부하·검토 대기 체류), 하단 목록 |
| 발표 모드 | `?present=1` | 큰 글씨, 사이드바 숨김, 게시물 이전/다음, 보고서로 복귀 |
| 알림함 | `/feed/inbox` | 이슈별 묶음, 읽음/안읽음, 보관 |
| 알림 설정 | `/feed/settings/notifications` | 이벤트 × 채널(앱 내·슬랙·이메일) 매트릭스 |
| 그룹 설정 | `/feed/settings/group?g=FD` | 게시물 유형(이름·색), 상태 이름, 멤버·관리자, 이슈 키 접두사, 비공개 여부 |
| 관리 콘솔 | `/feed/admin` | 사용자 목록·비활성화·시스템 관리자 지정, 그룹 목록 |
| 커맨드 팔레트 | 오버레이(Cmd/Ctrl+K) | 게시물 검색·생성·화면 이동·사용자 전환 |
| 발송 로그 | `/feed/dev/outbox` | 슬랙·이메일로 나갔을 메시지 목록(프로토타입 전용) |
| 시드 관리 | `/feed/dev/seed` | 리셋, 기본 시나리오 적재, JSON 내보내기·가져오기 |
| 시계 오프셋 | `/feed/dev/clock` | "오늘"을 앞뒤로 옮겨 기한 알림·보류 복귀를 바로 확인 |

## 데이터 모델

`server/feed/ddl.ts`가 원본이다. 게시물이 허브이고, 변경 이력(`events`)이 활동 로그·알림·보고서의 단일 원천이다. 이슈 키는 만들 때 `groups.key_prefix || '-' || seq`로 정해 `posts.key`에 저장하고, seq는 `groups.next_seq`에서 트랜잭션으로 발급한다.

## 상태와 전이

상태 6개, 카테고리 3개(고정). 그룹은 상태 **이름**만 바꿀 수 있다.

| 카테고리 | 상태 |
|---|---|
| 열림 | 미해결(unresolved) · 진행 중(in_progress) · 검토 중(in_review) |
| 멈춤 | 보류(on_hold) |
| 닫힘 | 해결됨(resolved) · 취소(cancelled) |

전이 규칙(`transition`과 보드 드래그가 공유):

- 미해결 → 진행 중: 담당자 또는 그룹 관리자
- 진행 중 → 검토 중: 담당자(requestReview). 요청자가 없으면 작성자가 요청자 역할
- 검토 중 → 해결됨(approve) 또는 진행 중(reject, 댓글 필수): 요청자 또는 그룹 관리자
- 열림 어디서나 → 보류(사유 + 재개일) 또는 취소(사유): 담당자·요청자·작성자·그룹 관리자
  - 취소 사유: 중복 · 재현 안 됨 · 범위 밖 · 우선순위 낮음
  - 보류 사유: 의존성 · 의사결정 · 리소스 대기
- 보류 → 미해결: 재개일 도달 시 scheduler가 자동, 수동도 가능
- 해결됨·취소 → 미해결(reopen): 요청자·작성자·그룹 관리자. reopen_count 증가
- 상위 이슈: 하위가 전부 해결되면 자동으로 검토 중(요청자에게 알림)
- 시스템 관리자는 모든 그룹에서 그룹 관리자 권한을 가진다

진행률: 하위 이슈나 체크리스트가 있으면 자동 계산(하위는 해결된 비율, 체크리스트는 체크 비율, 둘 다 있으면 하위 우선), 없으면 수동.

## 역할

| 역할 | 할 수 있는 것 |
|---|---|
| 시스템 관리자 | 관리 콘솔, 모든 그룹의 그룹 관리자 권한, 비공개 그룹 보기 |
| 그룹 관리자 | 그룹 설정, 모든 전이, 승인 |
| 멤버 | 게시물 만들기·고치기, 규칙에 맞는 전이 |

비공개 그룹의 게시물은 멤버(와 시스템 관리자)만 본다.

## 알림

| 이벤트 | 앱 내 | 슬랙 DM | 이메일 |
|---|---|---|---|
| 배정(assigned) | ● | ● | |
| 멘션(mention) | ● | ● | |
| 댓글(comment) | ● | | |
| 상태 변경(status) | ● | | |
| 완료 요청(review_requested) | ● | ● | |
| 승인(approved) | ● | | |
| 반려(rejected) | ● | ● | |
| 기한 D-1·당일(due_soon) | ● | ● | |
| 기한 초과(overdue) | ● | ● | ● |
| 보류 재개(hold_resumed) | ● | | |
| 차단 해제(unblocked) | ● | | |
| 하위 이슈 완료(children_resolved) | ● | | |

표의 ●가 기본값이고, 사용자가 이벤트 × 채널로 바꾼다. 자기가 한 일은 알리지 않는다.

- 자동 구독: 작성자·담당자·요청자·이해관계자·댓글 작성자·멘션된 사람. 게시물별로 켜고 끈다(muted).
- 슬랙·이메일은 실제로 보내지 않고 `outbox`에 남긴다(`/feed/dev/outbox`).
- 기한 알림은 scheduler가 앱 시작 시와 1분 간격으로 돈다: D-1·당일·초과(하루 1회), `hold_until`이 지난 보류는 미해결로 복귀.

## 시드

첫 화면에서 활동 보고와 내 작업이 바로 차 있어야 하므로 4주치 이벤트를 과거 시각으로 나눠 넣는다.

| 시드 항목 | 수량·분포 | 의도 |
|---|---|---|
| 사용자 | 8명: 시스템 관리자 1, 그룹 관리자 2, 멤버 5 | 사용자 전환으로 역할별 화면 확인 |
| 그룹·팀 | 그룹 2개(접두사 FD, DX), 팀 각 2개. DX는 비공개 | 비공개 경계 확인 |
| 게시물 유형 | 그룹마다 5개: 버그·기능·질문·데이터 요청·업무 기록 | 업무 기록 유형이 주간 보고의 재료 |
| 게시물 | 60개. 미해결 20 · 진행 중 15 · 검토 중 6 · 해결 12 · 보류 4 · 취소 3. 기한 지난 것 5, 이번 주 기한 8. 형식 이미지 30 · 차트 15 · 코드 10 · 동영상 5 | 보드 열이 전부 차고, 기한 알림과 승인 대기가 보임 |
| 관계 | 상위/하위 3세트(하위 3~4개), 차단 2쌍, 중복 1쌍 | 상위 진행률 자동 계산과 차단 표시 확인 |
| 댓글 | 120개. 대댓글 40, 반응 60, 투표 1, 멘션 15 | 스레드·멘션 알림 확인 |
| 이벤트 | 4주치. 매일 생성 1~3, 상태 변경 2~5, 완료 0~2 | 활동 보고와 리드타임이 첫 화면부터 의미 있게 |
| 알림 | 첫 사용자 기준 안읽음 10개, 승인 대기 2개 | 알림함과 내 작업 요약 띠 확인 |
| 저장된 뷰 | 그룹당 공유 뷰 2개(이번 주 기한, 검토 대기), 개인 뷰 1개 | 사이드바 고정 확인 |

## 프로토타입 전용 장치

모두 `/feed/dev` 경로나 팔레트 명령으로 격리해 나중에 떼어내기 쉽게 한다.

| 장치 | 위치 | 동작 |
|---|---|---|
| 사용자 전환 | 상단 아바타 메뉴, 팔레트 "사용자 전환" | 사용자 id를 localStorage에 저장. 권한·알림·내 작업이 바뀌는지 확인 |
| 발송 로그 | `/feed/dev/outbox` | 슬랙·이메일로 나갔을 메시지를 시간순으로 |
| 시드 관리 | `/feed/dev/seed` | 리셋, 기본 시나리오 적재, JSON 내보내기·가져오기 |
| 시계 오프셋 | `/feed/dev/clock` | "오늘"을 앞뒤로 옮긴다 (`PUT /api/feed/system/clock`) |
| AI 어댑터 배지 | 상단 바 | "Chrome 내장 AI" 또는 "흉내". 누르면 availability 값과 모델 다운로드 버튼 |

## AI 어댑터

- 시작 시 `LanguageModel.availability({ expectedInputs: [{ type: 'text', languages: ['ko'] }], expectedOutputs: [{ type: 'text', languages: ['ko'] }] })`. 전역 `LanguageModel`이 없으면 흉내.
- `available`이면 chrome 어댑터. `downloadable`이면 배지에서 누를 때 `create({ monitor })`로 다운로드 진행률을 보여주고 끝나면 chrome. `downloading`·`unavailable`이면 흉내.
- 한국어가 공식 지원되지 않아 `NotSupportedError`가 날 수 있으므로 create·prompt를 try/catch로 감싸고, 실패하면 그 세션은 흉내로 내려가 배지를 갱신한다.
- chrome 어댑터는 `initialPrompts`에 시스템 프롬프트, `responseConstraint`에 JSON 스키마를 써서 suggestFields 출력을 고정한다. 보고 초안은 `promptStreaming`으로 스트리밍한다.
- 흉내 어댑터는 결정적이다. 보고 초안은 활동 로그를 날짜·담당자별 템플릿 문장으로 조합하고, suggestFields는 제목 키워드 규칙("오류·안 됨" → 버그, "요청" → 데이터 요청 등)으로 채운다. 요약은 첫 문단과 마지막 댓글을 잇는다.
- 타입은 `@types/dom-chromium-ai`. AI는 화면(main thread) 쪽 모듈이다(`src/feed/ai`).
